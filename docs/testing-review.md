# Ревью и исправления тестов — 3 ноября 2026

## Исправлено

### 1. Перетаскивание карточек

Ранее сторона вставки (`before`/`after`) вычислялась только при смене цели в `onDragOver`. При движении над той же карточкой значение устаревало. Кроме того, вложенная карточка и её колонка одновременно являлись целями: выбор всей колонки мог сохранить прежний порядок.

В `KanbanBoard.tsx`:

- При выборе цели карточка под указателем имеет приоритет перед колонкой; при отсутствии попадания указателя используется пересечение прямоугольников.
- Индикатор вставки обновляется через `onDragMove`.
- Окончательная сторона вставки пересчитывается в `onDragEnd` по текущим координатам.

Браузерные проверки покрывают перестановку вверх и вниз, сохранение порядка после перезагрузки, перенос в другую колонку и откат при ошибке сервера. Отметка ожидаемой ошибки `test.fail` удалена.

### 2. Данные и независимость сценариев

Все Playwright-сценарии используют общую fixture из `e2e/board-fixture.ts`:

- У создаваемых задач уникальные названия.
- Задачи, созданные через API, регистрируются непосредственно в fixture.
- Задачи, созданные через интерфейс, регистрируются по успешному ответу на POST.
- После каждого сценария удаляются только его задачи; уже удалённая задача с ответом 404 допустима.
- Общая очистка таблицы в global setup удалена. Setup только проверяет имя базы `kanban_test` и наличие таблицы.
- Тесты выполняются одним worker: сохранение перетаскивания отправляет снимок всей доски, поэтому параллельные сценарии с одной базой могли бы перезаписывать состояния друг друга. Для параллельного масштабирования понадобятся отдельные базы/серверы на worker.
- Помощник reloadTasks принимает только ответы на запросы новой навигации: поздний ответ от старой страницы больше не принимается за результат reload. Обе карточки перед перетаскиванием прокручиваются в видимую область.
- Поиск проверяет и наличие совпадений, и отсутствие посторонних карточек. Проверки редактирования ограничены конкретной формой.

Не запускать два независимых набора одновременно против одной базы. Тестовая база остаётся отдельной от рабочей.

### 3. GitHub Actions

В `.github/workflows/ci.yml` добавлен отдельный job `Playwright E2E`:

1. PostgreSQL 17 с отдельной базой `kanban_test` и проверкой готовности.
2. Node.js 26, установка зависимостей фронтенда и бэкенда из lock-файлов.
3. Создание таблиц через существующий `server` скрипт `db:setup`.
4. Проверка типов самих E2E-тестов через `tsconfig.e2e.json`.
5. Установка Chromium и системных зависимостей.
6. Запуск Playwright; серверы приложения запускает конфигурация Playwright.
7. Сохранение HTML-отчёта, скриншотов и трассировок ошибок в `playwright-results` на 7 дней.

Workflow запускается при push в любую ветку, при PR в main и вручную через workflow_dispatch. Существующий job `checks` продолжает проверять фронтенд и бэкенд. Секреты для временной тестовой базы не нужны; production-база не используется.
